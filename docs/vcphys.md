- **Broadphase:** `core/World.h` defines an 80×80 grid of 50m sectors; `CPhysical::CheckCollision` / `ProcessCollisionSectorList` traverse sector linked lists, suppress duplicates with scan codes, and reject by bounding spheres.
- **Narrowphase:** `collision/Collision.cpp:CCollision::ProcessColModels` transforms primitives between models, applies bounding-box rejection, then **scans every target triangle** to build candidates; there is no per-mesh BVH.
- **Scaling:** mesh work is approximately `T + (S + L) × K` primitive tests per model pair, with T mesh triangles, K surviving candidates, S body spheres, L suspension lines. Cars normally have four wheel lines.
- **Worst ARM arithmetic:** `TestSphereTriangle` and `ProcessSphereTriangle` repeatedly construct triangle bases using square roots, division, dot/cross products; wheel `ProcessLineTriangle` queries add further mesh traversal.
- **Memory:** `CColModel` stores separate primitive, vertex, triangle and plane arrays; indexed vertices and linked entity lists scatter reads. `CompressedVector.h` defaults here to **12-byte float vertices**; `COMPRESSED_COL_VECTORS` reduces them to **6-byte fixed-point vertices**.
- **Plane churn:** `CCollision::CalculateTrianglePlanes` maintains a 50-model LRU (`core/config.h:NUMCOLCACHELINKS`); misses allocate and rebuild planes in `CColModel::CalculateTrianglePlanes`, potentially causing spikes.
- **Cache qualification:** Cortex-A5 supports L1 caches; “without cache” should mean verified disabled/unavailable caches on this port. If disabled, restoring cacheable RAM and I/D caches likely outranks physics tuning. [Arm documentation](https://documentation-service.arm.com/static/602f9e0483844146ae044205)
- **PS2 evidence:** this tree’s `GTA_PS2` configuration enables `VU_COLLISION`, compressed vertices/planes, scratchpad working buffers and VU0 collision microcode (`VuCollision.cpp`, `vu0Collision_*.s`). It supports SIMD/local-memory optimization; it does **not** establish fewer PS2 solver iterations.
- **NEON targets:** batch sphere transforms and sphere/box/plane rejection in `ProcessColModels`; batch triangle plane tests and `ProcessLineTriangle` math. Use four independent tests per batch with contiguous data; isolated three-component `DotProduct` replacements offer less benefit.
- **Verdict:** collision is a credible major CPU bottleneck during dense traffic/crashes, especially uncached; source alone cannot establish it as the FPS bottleneck over rendering, animation or AI. Measure collision time, calls, triangles tested and retries separately from those systems.
- **Priority 1 — fewer active bodies:** extend existing `STATUS_SIMPLE` / `CAutomobile::ProcessControl` → `CCarCtrl::UpdateCarOnRails`; retain full physics near the player and interactions, sleep debris, reduce ambient traffic/ped counts.
- **Priority 2 — fewer mesh tests:** simplify static collision assets while preserving road surfaces, curbs and walls; add compact per-mesh triangle clusters/BVH before `ProcessColModels` and line queries. Group nearby triangles/vertices; trial compressed vertices within the 64MB budget.
- **Priority 3 — fewer retries:** trial reducing `CWorld::Process`’s four retry passes to one or two for NPCs/debris; preserve player recovery. Coarsen NPC displacement sampling cautiously; validate tunnelling and pileups before imposing caps.
- **Priority 4 — cheaper shapes:** use fewer body spheres and reduced wheel/ground probes for nearby NPC cars; preserve player suspension. `CPed::ProcessEntityCollision` already uses simple body models and cached ground polygons—reduce distant NPCs to one/two spheres plus a ground probe, preserving steps.
- **Priority 5 — bounded scheduling + SIMD:** retain 30Hz near-player physics; stagger distant updates at 10–15Hz, respecting displacement sampling. A 30Hz cap alone saves nothing versus the existing default. Then NEON-vectorize the surviving batches; validate collision boundaries and handling.
