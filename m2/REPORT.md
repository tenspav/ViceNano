PASS: the pinned librw core now renders the checker cube through `Camera`, `SetRenderState`, `im3d::Transform` and ushort indexed primitives in the ARM NanoEmu app. A blended Im2D overlay and a second 3D cube drawn after it prove scene/overlay coexistence and camera/state restoration.

The host semantic test passes: legal/illegal engine transitions, deferred GL until rendering/resource creation, positive-Z camera projection and handedness, state round trips, texture addressing, unsupported fog rejection, reciprocal-Z Im2D clip coordinates, Im2D-to-Im3D restoration, raster deletion and balanced RW allocations. Four full engine lifecycle cycles return allocation balance to zero. Run `./check-host.sh`; output is in host-check.log. The GL recorder tests semantics, not rendering; screenshot proof uses the real ARM/SDK/RetailOS/MBX path.

Local `vendor/librw` derives from 0ad67ee226ea51beb3f465cb8857195e4db16029. New GLES1 selection, Device/Driver hooks and fixed pipeline replace the GL3 shader/VAO path. The camera and immediate-vertex conventions follow the pinned GL3 backend. Depth read/write, culling, blending, alpha, texture/filter/address states are stored and applied at draws. Im2D handles camera Z in clip-space and is bounded to 1024 vertices. Im3D uses client arrays; M1b separately proves VBOs. Base-level POT RGB565/RGBA4444 rasters have matched creation/lock/upload/destruction. Fog, stencil, GS alpha emulation, lighting and image conversion are unfinished; unsupported requests are counted. The cube does not require them. Default atomic pipeline follows in M3.

Lifecycle tests exposed 440 bytes of upstream default-pipeline leaks (including PS2's material pipeline). Engine stop and PS2 driver close now reclaim them and reset cached PS2 pointers. Host converter support for other native platforms remains available. The Nano-only build excludes foreign driver startup and host file/image services; its FileFunctions are unavailable, not a streaming implementation.

ARM Cortex-A5 Thumb soft-float package: 62,188 bytes, image 58,792, span 89,200, 843 relocations; SDK Thumb-FP gate passes. The local compact linker includes constructor arrays in PROGBITS `.data` because SDK mkrelocapp ignores SHT_INIT_ARRAY. `--target1-rel` and the runtime's relative constructor walker avoid unsupported absolute constructor relocations. ARMv4 Thumb no-FP newlib archives avoid MOVW/MOVT absolute relocations in prebuilt ARMv7 archives. C linkage is explicit for SDK GL/surface/heap calls.

The runner replaces the existing Mario Kart executable through an in-memory NAND patch and launches its page-3 icon. Emulator code opens the disk O_RDONLY. Original FAT/directory/cluster chains are unchanged; original source size, mtime and patched-block hashes are checked after the run. The larger slot pads HRL1 to 1,111,628 bytes, so runtime memory includes this padding; package size alone does not equal load cost. No physical device is touched. The reference reVC tree and SDK stay read-only.

Failed launches exposed cached directory metadata and the missing constructor section; failed-launch retains a screenshot/log. A nested-file launcher was abandoned after direct launch of the existing larger slot succeeded. Physical-device and long-duration gates remain unverified. Continuing to M3.
